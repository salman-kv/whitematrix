2. Architecture (MVC + Provider)

Folder (lib/)Role
models/M · plain data classes: Product, ShopCategory, CartItem, Order, AppUser.
views/V · the screens: splash, login, home, categories, search, product, cart, wishlist, profile, settings.
controllers/C · state and logic: Auth, Catalog, PagedProducts, Cart, Wishlist, RecentSearch, Nav, Theme.
services/The only code that reaches data: ProductRepository (API), StorageService (phone storage), ProductQuery (search/filter/sort rules), MockData (offline fallback).
widgets/Reusable UI: product card, paged product grid, buttons, text field, filter sheet, shimmer, empty states.
core/Theme, colours, routes, validators, responsive helpers, demo accounts.
Screen tap → Controller method → Service (API or storage) → Controller updates state → notifyListeners() → Provider rebuilds the screen

Controllers are created once in main.dart with MultiProvider. Screens read them with context.watch (rebuild on change) or context.read (just call a method).

3. Data and API

Where the product data comes from

ProductRepository calls GET https://dummyjson.com/products?limit=0&select=.... limit=0 returns every product in one response. Each item is turned into a Product object; vehicle categories are dropped, leaving 22 categories grouped into 6 app categories.

  • The result is cached in memory, so every screen shares one list.
  • The list is shuffled with a fixed seed (7): the feed looks mixed but is the same on every launch.
  • If the request fails, about 50 built-in placeholder products are used and Home shows an "Offline" note.

What each value is based on

ValueSource
Name, description, brand, price, discount %, rating, stock, imagesFrom the API response.
"Original" (struck-through) priceCalculated: price ÷ (1 − discount%).
Review countGenerated from the product id (the API has no review counts).
Colour and size optionsThe API has no colour or size data, so every product shows one default choice: Color "Default" and Size "One size".
Best Deals, category counts and coversCalculated from the loaded products.
Search, sort, price and category filtersDone on the phone by ProductQuery.
Banners, popular searches, notification textFixed text in the code.

5. Login and accounts

There is no backend. Three accounts are fixed in core/demo_accounts.dart and accept the e-mail or phone number. A one-second delay imitates a network call. Only the logins are fixed; every account starts with an empty cart and wishlist.

6. Design, font and theme

  • Font: Poppins, loaded by google_fonts and applied to the whole text theme. It is downloaded the first time it is needed, so the first launch needs internet; without it the system font is used.
  • Colours: AppColors holds the brand blue #1F64F2 and status colours as constants; background, card, border and text colours are getters that return a light or dark value.
  • Theme: AppTheme.build() creates the Material 3 theme. Light, Dark and System are chosen in Settings and saved by ThemeController.
  • Responsive: product grids use 2 to 5 columns depending on width; forms scroll so the keyboard never hides a field.
